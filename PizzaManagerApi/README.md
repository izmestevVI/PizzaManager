⚙️ Pizza Manager API

Бэкенд-часть приложения, реализованная на .NET 10. Это высокопроизводительное RESTful API, спроектированное с учетом принципов чистой архитектуры и асинхронности.

🛠 Технологический стек

-   Runtime: .NET 10 (C#)
-   ORM / Data Access: [Dapper](https://github.com/DapperLib/Dapper) --- для максимально быстрых и гибких SQL-запросов.
-   Database: PostgreSQL.
-   Migrations: [DbUp](https://dbup.readthedocs.io/) --- SQL-first подход к миграциям (скрипты в папке `Scripts`).
-   API Documentation: [Scalar](https://scalar.com/) --- современная и интерактивная альтернатива Swagger.

🏗 Архитектура

Проект следует многослойной архитектуре для обеспечения тестируемости и разделения ответственности:

1.  Controllers: Обработка HTTP-запросов и маршрутизация.
2.  Services: Бизнес-логика приложения.
3.  Repositories: Непосредственное взаимодействие с базой данных через SQL.
4.  DTOs: Объекты передачи данных, исключающие прямое использование моделей БД в API.
5.  Models: Сущности базы данных.

📡 Основные эндпоинты

API разделено на три ключевых домена:

🍕 Управление пиццами (`/api/pizzas`)

Полный цикл CRUD: получение списка, просмотр деталей, создание, редактирование и удаление пицц.

📋 Заказы (`/api/orders`)

-   Создание новых заказов.
-   Просмотр истории заказов.
-   Обновление статуса заказа (например, "В пути" или "Доставлено").

📖 Справочники (`/api/dictionary`)

Вспомогательные эндпоинты для фронтенда: получение категорий, ингредиентов, списков клиентов и курьеров.

🚀 Особенности реализации

-   Primary Constructors: Использование новых возможностей C# для лаконичного внедрения зависимостей (Dependency Injection).
-   Embedded Migrations: SQL-скрипты встроены в сборку как `EmbeddedResource`, что гарантирует их автоматическое выполнение при старте контейнера.
-   Global Usings & Nullable: Код написан с соблюдением современных стандартов типизации и безопасности.

📦 Сборка и Docker

Проект содержит собственный `Dockerfile` для многоэтапной сборки (Multi-stage build), что минимизирует размер итогового образа. В составе всей системы API общается с БД по внутренней сети Docker.

* * * * *

Как использовать

1.  Перейдите в корень проекта.
2.  Запустите через Docker Compose: `docker-compose up api`.
3.  Откройте документацию: `http://localhost:8080/scalar/v1`.
